# 演示指引

> 配合 `assets/screenshots/` 中的截图，或直接打开运行中的应用逐页走查。
> 每个环节标注了**可直接核查的证据**与**必须主动说明的边界**。

---

## 1. 演示前准备

### 1.1 启动

```bash
python app.py                    # 启动，等 30–60 秒（需载入首个病例的四序列体数据）
ssh -L 7860:127.0.0.1:7860 ...   # 远程服务器需端口转发
```

### 1.2 预热

建议提前执行一次 AI 分割，让科研 Dashboard 有真实数据可展示。
未预热时科研页显示空状态——这是设计行为，不是故障（见 §7.2）。

### 1.3 先确认当前运行模式

| 模式 | 触发条件 | 界面标识 |
| --- | --- | --- |
| **LLM 工具调用模式** | 已配置 API 且通过函数调用探测 | 「LLM 工具调用模式（真实函数调用）」 |
| **固定工作流模式** | 未配置 API，或端点不支持函数调用 | 「固定工作流模式（未经 LLM 决策）」 |
| **报告模板生成** | 点击模板按钮 | 「已由确定性模板生成」 |

三种模式在界面上严格区分。**演示前先确认当前处于哪一种，并如实说明**——
未配置 API 时界面会明确标注「未经 LLM 决策」，不会伪装成真实调用大模型。

### 1.4 讲解纪律

- 所有数字均为真实运行结果，不做估算、不做复述
- 凡未验证的功能，主动说明「这块没做」或「这块未验证」
- 严格区分**算法评估指标**（Dice）与**临床诊断指标**，两者不等价

## 2. 工作台（截图 `01_dashboard.png`）

**要说明的问题**：影像科的辅助诊断、教学、科研三件事，
目前由三套互不相通的工具承担，同一个病例的状态在它们之间必然失真——
医生在分割工具里改了掩膜，教学案例里还是原始预测，科研端对不上。

**本项目的做法**：把三者收敛到**同一个 `Case` 对象**上，
影像、掩膜、测量值、审核状态始终指向同一条记录。

**要点**：首页四张能力卡即四条主线，当前状态面板显示已加载病例与序列。

## 3. 智能阅片 · 真实 AI 分割（截图 `02` `03`）

### 3.1 操作

选择病例 → 查看输入检查结果 → 点击「运行 AI 分割」。

### 3.2 观察点

**输入检查先于分割**：检查序列是否齐全、几何信息是否一致。
**不通过则阻止分割**——几何错位的掩膜会产生看起来合理但完全错误的数字，
比直接报错更危险。

**真实模型推理**：调用 MONAI 官方 BraTS SegResNet 权重，
输出全肿瘤（WT）、肿瘤核心（TC）、强化肿瘤（ET）三个**嵌套**区域。

**体积由确定性代码计算**：体素数 × 体素体积。
**LLM 不参与任何数值计算**——这是刻意的设计约束，理由见 §5.3。

### 3.3 可核查的证据

6 例公开 BraTS 2020 病例，模型预测 vs 专家参考标注：

| 区域 | 平均 Dice | 标准差 |
| --- | ---: | ---: |
| WT 全肿瘤区 | 0.8889 | 0.0604 |
| TC 肿瘤核心区 | 0.9243 | 0.0155 |
| ET 强化肿瘤区 | 0.8400 | 0.0327 |

与 MONAI 官方公布水平一致，说明**权重、通道顺序、预处理与后处理均正确落地**。

### 3.4 必须说明的边界

> ⚠️ **样本量仅 6 例，属小样本实验结果，不构成对模型泛化能力的统计结论。**
> 参考标注本身也存在观察者间差异。

## 4. Agent 工具调用（截图 `06` `11` `12`）

### 4.1 操作

切到「AI 报告」，输入例如「分析当前病例，查询分割结果，整理区域体积，并生成报告草稿」。

### 4.2 观察点

**Agent 的职责被刻意限定**为：选工具、排顺序、把结构化结果组织成回答。
影像分析交给经过验证的分割模型，数值计算交给确定性代码。

**执行记录是可核查的**：每次工具调用都带状态与毫秒级耗时，
因此能确认工具**确实执行了**，而不是模型叙述了一遍。

以 DeepSeek `deepseek-chat` 的真实记录为例：

```
执行模式 : llm_tool_calling          ← 真实 LLM 决策
模型调用 : 3 次 API 往返
工具调用 : 6 次
  1. [ok] get_case_info              0 ms   病例 BraTS20_Training_001
  2. [ok] validate_mri               0 ms   输入检查通过
  3. [ok] get_segmentation_results   8 ms   MONAI/brats_mri_segmentation v0.5.4
  4. [ok] calculate_volume           4 ms   WT 192.53 / TC 47.37 / ET 30.06 mL
  5. [ok] get_review_status          0 ms   审核状态: unreviewed
  6. [ok] generate_report_draft    313 ms   已生成待审核报告草稿（1062 字符）
耗时     : 模型 4.42s / 工具 0.32s / 总计 4.74s
一致性校验: 通过（体积与病例编号与工具返回值全部一致）
```

未配置 API 时运行在固定工作流模式，由关键词路由到确定性工具链，
执行记录通常为 3 次调用（获取病例信息、读取分割结果、读取确定性计算的体积）。

### 4.3 工具注册表

共 **9 个**已注册工具，每个都有明确的 JSON Schema：

`get_case_info` · `validate_mri` · `run_segmentation` · `get_segmentation_results` ·
`calculate_volume` · `get_review_status` · `get_model_evaluation` ·
`generate_report_draft` · `get_research_feedback`

### 4.4 安全边界（四条，均有测试覆盖）

1. **参数校验**——模型返回的每个参数按 JSON Schema 校验（类型 / 必需项 /
   未声明属性 / 枚举值）。不合法直接返回 `error` 并把原因回灌给模型，
   **不会拼进 Python 调用**。
2. **不可自行改变状态**——`run_segmentation` 属于消耗算力、改变系统状态的操作，
   **即使模型自己传 `confirm=true` 也返回 `refused`**，确认必须来自用户点击按钮。
3. **不可审批报告**——`generate_report_draft` 只能写入 `pending_review` 修订，
   审批是人的动作，Agent 够不到。
4. **无危险工具**——注册表中不存在 shell / 文件读写 / 删除类工具。

### 4.5 回答一致性校验

回答中出现的每个体积数值（mL）与病例编号，都会与工具**真实返回值**比对。

不一致时**不会用模型的说法覆盖工具结果**，而是在回答旁标注提示，
由用户以工具结果为准。提示词中也禁止模型输出 Dice 这类科研指标——
那属于算法评估，不属于影像报告。

### 4.6 模型选择

「AI 报告」页的**推理模型**选择器支持 `DeepSeek / 本地 Qwen3-0.6B / 自动`。

| | DeepSeek | 本地 Qwen3-0.6B |
| --- | --- | --- |
| 配置来源 | `.env` | `LOCAL_LLM_BASE_URL`（默认 `127.0.0.1:8080/v1`） |
| 运行方式 | 官方 HTTPS API | llama.cpp，普通用户进程 |
| 推理设备 | 服务商 | **本机 CPU**（0 MB 显存） |
| 数据流向 | 结构化数据发往第三方 | **不出本机** |
| 平均耗时（实测） | 4.7 s | 207.8 s |

**默认是 DeepSeek**：交互式演示无法承受本地 CPU 每轮 100–425 秒的等待。

**不做静默外部回退**：本地服务不可用时，`自动` **不会**自动改用 DeepSeek。
把病例结构化数据发往第三方服务，与在本机跑模型是两件不同的事，
必须由用户明确选择：

- 选择「自动」且本地不可用 → **拒绝执行**并说明原因
- 明确选择 DeepSeek → 视为用户确认（界面标注「数据将发送至第三方」）
- 一旦发生回退 → 界面显示 `⚠ 已回退：<原因>`

每次回答都标注**实际使用的服务商**。

### 4.7 必须说明的边界

> ⚠️ 本地模型对比仅覆盖 **3 个任务、1 个病例、1 次运行**，不能据此得出泛化性结论。
> 完整数据见 [MODEL_COMPARISON.md](MODEL_COMPARISON.md)。

## 5. 报告与审核（截图 `05` `05b`）

### 5.1 观察点

- 报告默认状态为 `pending_review`，人工确认后才标记已审核
- 审核记录保存为**独立修订版本**，**不覆盖**原始模型预测
  （否则科研反馈失去依据）
- 报告支持两条生成路径：确定性模板、LLM 叙述；两者都会做数值回填与一致性校验

### 5.2 为什么审核不可绕过

医疗场景下不能让 AI 自行定稿。审核是**人的动作**，
Agent 既不能触发分割，也不能批准报告。

## 6. 教学模式（截图 `07` `07b` `08`）

### 6.1 操作

切到「教学模式」，点击「加载练习」。

### 6.2 关键约束：提交前不泄露答案

教学模块复用**同一个病例、同一份参考标注**。

**后端权威校验**：未提交时点击「显示参考标注」会被拒绝，
提示「参考答案在提交前不可查看」。这不是前端隐藏——
`teaching.reveal_allowed()` 是后端校验，所有渲染路径都走它，改前端绕不过去。
该属性有单元测试专门断言。

### 6.3 提交后的反馈

- 上传掩膜 → 给出与参考标注的 **Dice、体积差、漏分割与过度分割体素数**
- 只提交文字 → 给出**结构化核对清单**，并明确写清**这不是分数**
- 涉及病理分级、治疗建议的 → **明确标注不自动评分**，交给带教老师

> **本系统没有临床金标准，不评临床对错。** 教学反馈只反映与特定标注的一致性。

## 7. 科研反馈（截图 `09` `09b` `09c` `09d`）

### 7.1 定位

科研模块**不做自动重训**，做的是**把模型误差变成可查询的数据**。

### 7.2 两条统计规则

- **只聚合真实测量值**——没有参考标注的病例贡献为零，而不是贡献一个 0 分
- **空是合法状态**——没有数据就显示空状态，不显示 0

样本量不足时如实标注。例如 n=1 时显示「样本量 1，标准差不适用」，
而不是显示 σ=0.000（那读起来像「完全一致」，实为「无法测量」）。

### 7.3 错误分类与可视化

错误分类由**人工确认**后写入，系统只给预选建议。
提供误差可视化与 CSV 导出，可直接进入下一轮模型迭代的讨论。

### 7.4 人工修正掩膜回流

1. 用外部工具（如 3D Slicer）修改掩膜后上传
2. 系统校验：**尺寸、affine、方向、标签编码、病例编号**
3. 给出与模型预测的**差异分析**
4. 保存为**独立修订版本**，并沉淀为科研记录

三类掩膜分别存储、各自带来源标签，**互不覆盖**：
数据集参考标注 / 模型预测 / 人工修正。

> ⚠️ 人工修正掩膜由用户上传，**未经具备资质的医师审核**。
> 演示路径（用参考标注模拟修正）在各处明确标注为演示，不得当作真实人工修正精度。

## 8. 演示中应主动说明的边界

| 边界 | 说明 |
| --- | --- |
| **6 例是小样本** | 不构成对模型泛化能力的统计结论 |
| **无真实用户验证** | 用户价值判断均为基于公开资料的假设，未经医生/学生实测 |
| **模型未做外部验证** | 仅在 BraTS 2020 同源数据上验证，未做多中心测试 |
| **无临床金标准** | 教学模块不评临床对错 |
| **演示路径有标注** | 模拟修正明确标注为演示 |
| **不做病理推断** | 分割模型看不到组织病理，生成类型/分级/治疗建议即为编造 |
| **本地模型验证有限** | 仅 3 个任务、1 个病例、1 次运行 |

## 9. 常见问题

| 问题 | 回答要点 |
| --- | --- |
| 为什么不用多 Agent 框架？ | 任务本身不需要；多 Agent 只会增加不可观测性。单 Agent + 工具注册表已覆盖需求 |
| 怎么保证 LLM 不编造数值？ | 数值全部由确定性代码算好后原样填入；LLM 只写叙述段落，提示词里附的是结构化事实；事后还有一致性校验 |
| 为什么让 Agent 无法自己跑分割？ | 消耗算力、改变系统状态的操作必须由用户确认。即使模型自己传 `confirm=true` 也会被拒绝 |
| 标签编码为什么要显式声明？ | 同一个整数 `3` 在 BraTS 中不存在、在 MSD 中是强化肿瘤。猜错会让所有 Dice 失去意义，因此声明 + 实测校验 |
| 参考标注可靠吗？ | 参考标注本身存在观察者间差异，界面明确写「只反映与**特定**标注的一致性，不等于临床准确性」 |
| 为什么默认用远程 API？ | 现场演示无法等待本地 CPU 每轮 100–425 秒；本地模型保留为一键可切选项 |
| 本地模型慢多少？ | 正确性持平，平均耗时 207.8 s vs 4.7 s，约 44×（纯 CPU，共享机器负载较高） |
| 怎么扩展到其他部位？ | `cases.py` 的适配器模式支持新增数据集（声明模态映射与标签约定）；模型换成对应的 MONAI bundle 即可 |
| 遇到过的最大技术问题？ | 归一化语义错误：手写 `(x-μ)/σ` 作用于整个体积，去颅骨数据背景被推到约 −4σ，**WT Dice 从 0.9255 掉到 0.3971**。教训是预处理必须调用官方实现。完整复盘见 [EVALUATION.md](EVALUATION.md) |
| 下一步做什么？ | **真实用户验证**——找 3–5 位医生/学生做可用性测试，验证「状态割裂是真痛点」这一核心假设 |
