# 模型对比：本地 Qwen3-0.6B vs DeepSeek

> **本文所有数字均来自真实执行**，不是估算或从别处引用。
> 原始记录：`outputs/llm_provider_comparison.json`

---

## ⚠️ 结论的适用范围（请先读这一段）

**只有 3 个测试任务、1 个病例、1 次运行。**

- 这**不是**模型能力评测，**不能**据此推断泛化性能
- 3/3 表示"这三个任务都完成了"，**不等于**"这个模型可靠"
- 单次运行无法反映方差；0.6B 这类小模型在不同提示下的波动可能很大
- 两个模型都只在这一个病例（BraTS20_Training_001）上测过

本文能支持的结论只有一条：**在这个项目的这套工具与这一个病例上，
0.6B 本地模型能够完成与 DeepSeek 相同的工具调用流程，但慢约 44 倍。**

各指标含义：

## 6. 观察到的差异（不只是速度）

### 6.1 冗余工具调用

`report` 任务中，本地模型调用了 **10 次**工具，DeepSeek 调用 **6 次**。
执行记录保存的是每次调用的工具名与状态（不是完整时序），据此可得：

| 模型 | 实际调用过的工具（去重） | 调用次数 | 被拒绝 |
| --- | --- | ---: | --- |
| 本地 | `validate_mri`、`get_segmentation_results`、`calculate_volume`、`generate_report_draft`、**`run_segmentation`** | 10 | 2 次（`run_segmentation`） |
| DeepSeek | `get_case_info`、`validate_mri`、`get_segmentation_results`、`calculate_volume`、`get_review_status`、`generate_report_draft` | 6 | 0 次 |

两点观察：

1. **本地模型多调用了 `run_segmentation`**，虽然每次都因权限被拒绝。
   小模型对"我无权执行此操作"的反馈吸收较慢，会重复尝试。
2. **本地模型重复调用**了已经拿到结果的工具（10 次调用只覆盖 5 个工具），
   而 DeepSeek 的 6 次调用对应 6 个不同工具，没有冗余。

> 注：原始记录保存的是工具名与状态集合，未保存严格时序，
> 因此这里不声称具体的调用先后顺序。

### 6.2 回答冗长

本地模型有时会把工具返回的 JSON 原样贴进回答（例如整段 `<case_info>` 内容），
DeepSeek 则会归纳成表格。这属于表达质量问题，不影响正确性。

### 6.3 速度快慢的原因

- 纯 CPU 推理，实测约 **3–5 tokens/s**
- 本机 80 核长期被他人作业占满（load average 70–95），线程争抢严重
- 若在空闲 GPU 上运行，通常可快 1–2 个数量级——但本机 GPU 全部被占用，
  为不影响他人任务，本地模型坚持 CPU 部署

## 7. 安全机制在两个模型下都成立

这是本次对比中最值得记录的部分：

| 检查 | 本地 Qwen3-0.6B | DeepSeek |
| --- | --- | --- |
| `run_segmentation` 被拒绝（即使模型传 `confirm: true`） | ✅ 2 次均被拒绝 | ✅ |
| 参数经 JSON Schema 校验 | ✅ | ✅ |
| 未注册工具被拒绝 | ✅ | ✅ |
| 回答数值一致性校验 | ✅ 通过 | ✅ 通过 |
| 无 shell / 文件读写 / 删除类工具 | ✅ | ✅ |

**小模型没有成为绕过安全机制的通道**——权限边界在工具层与校验层，
不在模型的配合度上。

## 8. 工程取舍

### 8.1 默认模型：DeepSeek

交互式演示默认使用 DeepSeek。本地模型单任务 100–425 s，
现场演示无法承受；`docs/DEMO_SCRIPT.md` 的 90 秒稿依赖秒级响应。

本地 Qwen3-0.6B 保留为**一键可切**的选项，用于展示"轻量本地部署 + 数据不出本机"的能力。

### 8.2 不做静默外部回退

本地服务不可用时，系统**不会**自动改用 DeepSeek。
切换到远程 API 意味着把病例结构化数据发往第三方服务，
这与在本机跑模型是两件不同的事，必须由用户明确选择。

- 选择「自动」且本地不可用 → 拒绝执行并说明原因
- 明确选择「DeepSeek（远程 API）」→ 视为用户确认
- 一旦回退，界面横幅会标注 `⚠ 已回退：<原因>`

### 8.3 传输层适配器

llama.cpp 的服务端不会把 Qwen3 输出的 `<tool_call>` 文本解析成结构化字段，
因此项目内有一个适配器做格式翻译。它只做翻译：
选哪个工具、传什么参数仍由模型决定，解析结果照样经过 JSON Schema 校验与工具注册表。
有测试专门断言 **文本态调用 `run_segmentation` 仍会被拒绝**。
