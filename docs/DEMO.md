## 讲解稿

### 0:00 – 0:12 ｜ 产品定位

> "这是 **Radiology Copilot**，一个诊教研一体化的医学影像 AI 工作台，第一版聚焦脑肿瘤 MRI。
>
> 它要解决的是：影像科的**辅助诊断、教学、科研**这三件事，今天由三套互不相通的工具承担，
> 同一个病例的状态在它们之间必然失真。我把它们收敛到**同一个病例对象**上。"

**（指向首页四张能力卡）** —— "所以首页就是这四条主线。"

### 0:12 – 0:32 ｜ 诊断辅助：真实 AI 分割

**（切到「智能阅片」，指向 MRI 与彩色叠加）**

> "选病例之后，系统先做**输入检查**——序列是否齐全、几何信息是否一致，
> 不通过就**阻止分割**，不会带着错位数据硬跑。
>
> 点『运行 AI 分割』，调用的是 MONAI 官方的 BraTS SegResNet 权重，
> 输出全肿瘤、肿瘤核心、强化肿瘤三个**嵌套**区域。
>
> **体积由确定性代码算**——体素数乘体素体积，LLM 不参与任何数值计算。"

**（指向右侧测量面板）**

> "这是真实推理结果：6 例公开数据上，全肿瘤区平均 Dice **0.89**，与 MONAI 官方水平一致。"

### 0:32 – 0:48 ｜ Agent：工具调用而不是"聊天"

**（切到「AI 报告」，在助手框输入"分析当前病例，并告诉我肿瘤区域的体积"）**

> "Agent 的职责我刻意限定为：**选工具、排顺序、把结构化结果组织成回答**。
> 影像分析交给经过验证的分割模型，数值计算交给确定性代码。
>
> 看下面的执行 trace——**三次真实工具调用**：获取病例信息、读取分割结果、读取确定性计算的体积。
> 每一次都返回明确状态，所以我能证明工具**真的跑了**，而不是模型描述了一遍。"

**（指向模式标签）**

> "这里是固定工作流模式，因为我没配 API Key。配了并且探测支持 function calling 就会
> 切成 LLM 工具调用模式。**API 不可用时界面会如实标注，不会假装调用成功。**"

**（指向报告内容）**

> "报告默认是**待审核**，人工确认后才标记已审核，而且审核记录是独立修订版本，
> **不覆盖**原始模型预测——否则科研反馈就失去依据了。"

### 0:48 – 1:05 ｜ 教学：同一份病例，答案先隐藏

**（切到「教学模式」，点击「加载练习」）**

> "教学模块复用**同一个病例、同一份参考标注**。
>
> 关键约束是：**提交前不泄露答案**——这一点有单元测试保证。
> 学生独立阅片、记录表现，可以上传自己做的掩膜，也可以只交文字。"

**（提交后指向反馈）**

> "提交后才解锁，给出与专家标注的 Dice、体积差、漏分割和过度分割体素数。
>
> 只交文字的话，我给的是**结构化核对清单**，并且明确写清**这不是分数**；
> 涉及病理分级、治疗建议的，我明确标注不自动评分，交给带教老师。
> **这个系统没有临床金标准，我不会假装能评临床对错。**"

### 1:05 – 1:20 ｜ 科研：把错误变成数据

**（切到「科研反馈」）**

> "科研模块不做自动重训，做的是**把模型误差变成可查询的数据**。
>
> 这里的两条规则很重要：**只聚合真实测量值**——没有参考标注的病例贡献为零，
> 而不是贡献一个 0 分；**空是合法状态**，没数据就显示空状态，不显示 0。
>
> 错误分类由**人工确认**后写入，系统只给预选建议。支持导出 CSV，直接进下一轮模型迭代的讨论。"

### 1:20 – 1:30 ｜ 收尾：我认为有价值的地方

> "最后一句话总结我的判断：
>
> 这个项目里**模型不是最难的部分**。真正决定它有没有用的，是——
> 数值必须可复现、来源必须可区分、Agent 不做它不擅长的事、以及**没有数据时如实说没有**。
>
> 开发过程中我在归一化语义上踩过一次坑：手写实现让 Dice 只有 **0.397**，
> 对照 MONAI 源码修正后到 **0.9255**。这段复盘我写在 `docs/EVALUATION.md` 里——
> **能定位并说清一个真实缺陷，比堆功能更能说明工程能力。**"

## 演示要点备忘

**一定要展示的**

1. **AI 分割的真实叠加与体积**（截图 03）—— 证明不是假数据
2. **Agent 执行 trace 的三次工具调用**（截图 06）—— 证明工具真的执行
3. **教学反馈里"这不是分数"的声明**（截图 08）—— 体现产品判断力
4. **科研 Dashboard 的真实 Dice 统计**（截图 09）—— 证明数据闭环

**主动说明的边界**

- 科研 Dashboard 只有 6 例，**样本量不足以支撑泛化性结论**
- LLM 真实工具调用路径已实现，但演示时**未配置 API Key**，运行在固定工作流模式
- 系统不做病理类型/分级推断，因为分割模型看不到组织病理

**可能被问到的问题**

| 问题 | 回答要点 |
| --- | --- |
| 为什么不用多 Agent 框架？ | 任务本身不需要；多 Agent 只会增加不可观测性。单 Agent + 工具注册表已经能覆盖全部需求 |
| 怎么保证 LLM 不编造数值？ | 数值全部由确定性代码算好后原样填入；LLM 只写叙述段落，且提示词里附的是结构化事实 |
| 为什么让 Agent 无法自己跑分割？ | 消耗算力、改变系统状态的操作必须由用户确认。即使模型自己传 `confirm=true` 也会被拒绝 |
| 标签编码为什么要显式声明？ | 同一个整数 `3` 在 BraTS 里不存在、在 MSD 里是强化肿瘤。猜错会让所有 Dice 失去意义，所以声明 + 实测校验 |
| 参考标注可靠吗？ | 参考标注本身也有观察者间差异，所以界面上明确写"只反映与**特定**标注的一致性，不等于临床准确性" |
| 怎么扩展到其他部位？ | `cases.py` 的适配器模式支持新增数据集（声明模态映射与标签约定）；模型换成对应的 MONAI bundle 即可 |
