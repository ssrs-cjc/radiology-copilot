# Radiology Copilot · 产品需求文档（精简版）

> 版本 v1.0 · 科研教学原型 · **不用于临床诊断**

## 1. 一句话定位

面向影像科医生、医学影像学生与科研人员的**诊教研一体化工作台**：
用同一个病例对象贯穿"AI 分割辅助诊断 → 结构化报告 → 教学练习 → 科研反馈"四个环节，
让模型在哪里出错这件事变成可追踪、可复用的数据。

第一版聚焦**脑肿瘤 MRI**（BraTS 四序列：T1 / T1ce / T2 / FLAIR）。

## 2. 问题与机会

### 2.1 现状痛点

| 角色 | 痛点 |
| --- | --- |
| 影像科医生 | 逐层勾画肿瘤边界耗时；手工测量体积重复且易错；AI 分割工具与报告系统割裂，结果要手工搬运 |
| 医学影像学生 | 缺少"隐藏答案—独立判断—与专家标注逐体素对比"的练习闭环；看片练习无法量化反馈 |
| 科研人员 | 模型在**哪些**病例上失败、失败成什么样（漏分割/过度分割/边界偏差），缺少结构化记录，只能靠翻日志与印象 |

三段流程今天由三套互不相通的工具承担，病例状态在它们之间必然失真。

### 2.2 产品机会

把三件事收敛到**一个 Case 对象**上：

- 诊断端产出**结构化、可核查**的定量结果
- 教学端复用**同一份影像与同一份参考标注**，且答案在提交前不可见
- 科研端自动沉淀**模型误差的结构化记录**，直接支撑下一轮模型迭代

## 3. 目标用户与核心场景

**主要用户**

1. **影像科医生**（辅助诊断）：读片时快速获得分割与体积，审核后生成报告草稿。
2. **医学影像学生 / 规培医师**（教学）：用真实病例做带客观评分的阅片练习。
3. **医学影像 AI 科研人员**（科研）：统计模型性能、定位困难病例、导出结构化数据。

**核心用户故事**

- 作为医生，我选择病例后能立刻看到四序列影像与 AI 分割叠加，并读到 WT/TC/ET 体积。
- 作为医生，我修改或确认结果后，系统生成一份**可编辑**的报告草稿，我确认审核后才标记为已审核。
- 作为学生，我在**看不到答案**的情况下阅片并提交，然后得到与专家标注的 Dice 与差异分布。
- 作为科研人员，我能看到模型在哪些病例上表现差、错误类型如何分布，并导出 CSV。

## 4. 产品原则（决定取舍的地方）

1. **真实功能优先**：每个按钮都有真实回调。没有实现的功能明确标注"计划功能"，不放假按钮。
2. **不虚构任何医学结论**：不做病理类型推断；不编造 Dice；无数据时显示空状态而不是 0。
3. **数值必须可复现**：体积与 Dice 由确定性代码计算，**禁止 LLM 推算**。
4. **来源必须可区分**：AI 预测 / 数据集参考标注 / 用户修正三者始终分开标注，绝不混为一谈。
5. **Agent 不做它不擅长的事**：LLM 负责选工具、组织流程、写叙述；**影像分析交给经过验证的分割模型**。

## 5. 功能范围

### 5.1 工作台首页

3 秒内说明产品是什么。四张能力卡 + 当前状态面板（当前病例 / 已加载序列 / 分割模型 / 最近分析 / 报告审核状态 / 科研反馈数）。
**不显示**虚构的患者数、准确率或使用量。

### 5.2 智能阅片

- 四序列切换、轴位层面滑动、灰度窗调节
- AI 分割叠加，掩膜显示/隐藏、透明度调节
- 当前层面 / 图像尺寸 / 体素间距 / 空间方向展示
- 输入合法性检查（可读性、序列完整性、几何一致性）——**检查不通过则阻止分割**
- 区域体积即时计算（WT / TC / ET，单位 mL）

### 5.3 AI 自动分割

- 调用 MONAI 官方 BraTS 分割 bundle（SegResNet）真实推理
- 输出 WT / TC / ET 三个**嵌套**区域，ET ⊆ TC ⊆ WT
- 与数据集参考标注计算 Dice 及体素级漏分割/过度分割
- 模型不可用时降级为**参考标注模式**（显著标注），功能不中断

### 5.4 AI 报告

- 由确定性模板生成结构化报告骨架，Agent 可提供 LLM 叙述段落
- 报告可编辑、可保存、可导出（Markdown + JSON）
- 默认状态**待审核**，人工确认后方为已审核；审核记录独立成版本，不覆盖原始预测

### 5.5 教学模式

- 复用同一病例；**提交前不泄露参考答案**
- 支持文字作答与掩膜文件上传
- 提交掩膜：计算 WT/TC/ET Dice、体积差、漏分割/过度分割
- 仅文字：输出**结构化核对清单**，并明确声明这不是分数、不评临床诊断

### 5.6 科研反馈

- 错误分类（漏分割 / 过度分割 / 边界偏差 / 输入异常 / 模型不适用 / 其他）
- Dashboard：评测例数、WT/TC/ET 平均 Dice、错误分布、困难病例清单、模型版本统计
- CSV 导出（评测指标 / 反馈记录）

## 6. 关键流程

```
选择病例
   ↓
输入检查（不通过则阻止后续）
   ↓
运行 AI 分割 ──→ 区域体积（确定性计算）
   ↓                    ↓
与参考标注比对 Dice       ↓
   ↓                    ↓
人工审核 / 修正 ──────────┘
   ↓
结构化报告草稿 → 人工确认审核 → 导出
   ↓
同一病例进入教学练习（默认隐藏答案）
   ↓
学生提交 → 客观评分反馈
   ↓
模型偏差写入科研反馈 → Dashboard 统计 → CSV 导出
                          ↓
                  下一轮模型改进的研究任务
```

## 7. 明确不做（v1 范围外）

| 不做 | 原因 |
| --- | --- |
| 病理类型 / 分级 / 治疗建议 | 分割模型看不到组织病理，生成这类结论即为编造 |
| 多平面重建、3D 重建 | v1 只做轴位浏览，保证核心体验可用 |
| 在线掩膜绘制编辑器 | 先支持文字作答 + 文件上传，验证闭环后再做 |
| 模型自动重训 | v1 只做"把错误变成数据"；新模型部署必须独立评估 + 人工批准 |
| 多 Agent 框架、微服务、消息队列 | 与 v1 目标无关，只会拖慢交付 |
| 真实临床部署 | 本产品是科研教学原型 |

## 8. 成功标准（v1）

- [x] `python app.py` 一条命令启动，浏览器可访问
- [x] 全部主要按钮有真实功能
- [x] 真实公开数据上跑通真实模型推理，并给出**可复现**的 Dice
- [x] 体积计算正确性有单元测试覆盖
- [x] 教学答案在提交前隐藏（有测试保证）
- [x] 科研反馈持久化并可导出
- [x] 同一病例在诊、教、研三个模块间状态一致

## 9. 后续迭代方向

1. **多平面 / 3D 阅片**，支持任意层面重建
2. **在线掩膜编辑器**，让学生在浏览器内直接勾画并即时评分
3. **纵向随访对比**，同一患者多时间点体积变化曲线
4. **多模型并列评测**，同一病例并行跑多个模型版本做误差对比
5. **模型迭代闭环**：把科研反馈导出的困难病例集接入主动学习流程

## 10. 风险与依赖

| 风险 | 现状与应对 |
| --- | --- |
| 模型泛化性 | 已在 BraTS 2020 上实测（见 `EVALUATION.md`）；不同中心数据需独立评估 |
| 参考标注本身有观察者间差异 | Dashboard 明确提示 Dice 只反映与**特定**标注的一致性，不等于临床准确性 |
| 网络无法访问 HuggingFace | 内置镜像回退；数据与权重均可用脚本预取 |
| 共享 GPU 资源 | 自动选择空闲显存最多、利用率最低的卡；不足时降级到 CPU |
