## 3. 过程中定位并修复的两个真实缺陷

保留这两条记录，因为它们正是"看起来能跑"和"真的正确"之间的差距。

### 3.1 归一化语义错误 → Dice 0.397

**现象**：首次端到端跑通时，WT Dice 仅 **0.3971**，预测体积约为参考的 1/4，
且 98% 的预测体素落在参考区域内（即系统性欠分割）。

**定位**：对照 MONAI `NormalizeIntensity._normalize` 源码发现，`nonzero=True` 时
**只对非零体素做标准化，背景保持为 0**：

```python
if slices is not None:
    img[slices] = (masked_img - _sub) / _div
```

而最初的手写实现是对整个体积做 `(x-μ)/σ`。BraTS 是去颅骨数据、背景全为 0，
于是背景被映射到约 **−4σ**。

**修复**：改为直接调用 MONAI 的 `NormalizeIntensity`，不再手写。

**结果**：

| | 修复前 | 修复后 |
| --- | ---: | ---: |
| BraTS20_Training_001 WT Dice | 0.3971 | **0.9255** |

### 3.2 灰度窗把背景计入百分位 → 影像全白

**现象**：阅片界面中 MRI 渲染成一片白色，无法辨认解剖结构。

**定位**：窗宽按切片百分位计算时把背景 0 一并计入。去颅骨 MRI 中约 70–85% 的
体素为 0，导致低百分位恒为 0，脑组织全部被压到量程顶端。

**修复**：百分位仅在**非零（组织）体素**上统计；同时修正了界面把
"百分位滑杆"当作**绝对灰度值**传入的语义错误。

**回归测试**：`tests/test_cases_imaging.py::test_background_does_not_collapse_the_window`
与 `test_window_never_produces_nan`。

在 BraTS20_Training_001 上，模型三个输出通道经阈值化后，有 **46 个体素**

## 5. 体积计算的正确性

体积由**确定性代码**计算：`体素数 × 体素体积`，体素体积由 affine 推导。

单元测试覆盖（`tests/test_metrics.py`）：

- 1 mm 各向同性下，体积(mL) = 体素数 × 0.001
- 各向异性间距（1×1×3 mm）下单体素 = 0.003 mL
- 空掩膜返回 0.0 而非 None
- 区域体积满足 `WT ≥ TC ≥ ET`
- 标签图 → 区域掩膜 → 标签图 往返一致
- `ET ⊆ TC ⊆ WT` 在任意 BraTS 标签图上成立

**LLM 不参与任何数值计算**；报告中的体积由确定性代码生成后原样填入。

```bash
$ python -m pytest tests/ -q

```

全部测试在**无数据集、无模型权重**的机器上通过（用临时目录中的小型 NIfTI 构造夹具）。

### 7.1 一轮 UI/UX 与工作流修复中定位并修复的缺陷

| 问题 | 现象 | 根因 | 修复 |
| --- | --- | --- | --- |
| **教学答案可被绕过** | 未提交时点击「显示参考标注」即可看到答案 | `on_teaching_reveal` 无条件 `submitted = True`，且前端隐藏按钮不是后端校验 | 在校验层新增 `teaching.reveal_allowed()`，所有渲染路径与按钮回调都走它；未提交时拒绝并在 `render_view` 中二次拦截 |
| **同一病例重复统计** | 同一病例跑两次后 n=2、σ=0.000 | `aggregate()` 统计的是**分析运行次数**而非**不同病例数** | 按 `case_id` 去重取最新一次运行；面板注明"多次运行只计一次" |
| **σ=0.000 误导** | n=1 时显示 `σ=0.000`，读起来像"完全一致" | 单样本标准差不适用，但直接输出了数字 | `spread_label()`：n<2 时显示"样本量 1，标准差不适用" |
| **误差对比图耗时 10s** | 三联图生成要等约 10 秒 | 对 ~9M 体素的全volume算 3 次区域掩膜 + 差异图 | 先取单片再算 2D 掩膜，并复用缓存；首次 4.3s → 重复调用 0.36s |
| **运行顺序不确定** | 同一秒内的多次运行顺序随机，"最新一次"成抛硬币 | `ORDER BY created_at` 精度只有秒 | 增加 `rowid DESC` 作为全序 tiebreak |
| **影像面板留白过大** | 去颅骨 MRI 大部分是背景，脑组织只占画面一小块 | 直接按原始矩阵渲染 | 新增 `head_bounding_box()` 按非零体素投影取**正方形**裁剪框（每卷只算一次，避免滚动时抖动） |
| **报告混入科研指标** | Dice / 漏分割体素数出现在影像报告正文 | 报告模板直接渲染了评测表 | 从报告与 LLM 事实集中移除，改为指向科研模块 |

每条修复都有对应回归测试（`tests/test_ux_fixes.py` 及既有测试文件的更新）。

### 8.3 本轮定位并修复的缺陷

| 问题 | 现象 | 根因 | 修复 |
| --- | --- | --- | --- |
| **函数调用探测不稳定** | 同一配置 `--dry-run` 成功、正式运行失败 | 探测使用 `tool_choice="auto"`，模型有权选择用散文回答而不调用工具 | 依次尝试「强制指定函数」→ `required` → `auto`，强制调用才能确定性判定端点是否支持 tools |
| **一致性校验误报（一）** | 回答正确却被判「病例编号不一致」 | 正则 `BraTS\d*_[A-Za-z]*_?\d+` 把标签约定字符串 `brats_2020` 误认成病例编号 | 收紧为 `BraTS\d{2,4}_[A-Za-z]+_\d{1,4}`，要求数字段必填 |
| **一致性校验误报（二）** | 回答引用「体素体积 0.001 mL」被判为体积不符 | 采集器只读取 WT/TC/ET 三个字段，遗漏 `voxel_volume_ml` | 改为递归扫描所有 mL 语义字段；同时补测试确保放宽后仍能抓到编造值 |
| **工具摘要输出对象 repr** | trace 显示 `<bound method ...provenance of ...>` | 调用方法时漏写括号，会把这串乱码喂给 LLM | 补上 `()` 并加回归测试 |
| **测试依赖本机 `.env`** | 存在真实 key 时降级行为测试失败 | 测试未与宿主环境隔离 | `conftest.py` 增加 autouse fixture，隔离 `LLM_*` 环境变量与 `load_dotenv`，避免测试产生真实 API 调用 |

### 8.4 安全边界（实测确认）

- **参数校验**：模型返回的参数按 JSON Schema 校验（类型/必需项/未声明属性/枚举），
  不合法返回 `error` 并把原因回灌给模型，不会拼接进 Python 调用
- **不可自行改变状态**：`run_segmentation` 即使模型传 `confirm=true` 仍被拒绝
- **不可审批报告**：`generate_report_draft` 只写 `pending_review` 修订
- **无危险工具**：注册表中不存在 shell / 文件读写 / 删除类工具
- **不发送敏感内容**：工具仅返回结构化字段（病例编号、序列、体积、模型版本），
  不含原始影像、文件路径或患者信息

## 9. 人工修正掩膜回流（Milestone 4）

闭环的最后一环：把**人的判断**接进科研数据，而不只是模型对标注。

### 9.1 流程与验证

```
上传 NIfTI（3D Slicer 等外部工具修改后）
  → 校验：尺寸 / affine / 空间方向 / 标签编码
  → 区域转换（支持 BraTS 标签图 与 单一区域二值掩膜）
  → 三联图：原始预测 | 修正结果 | 差异区域（紫=修正新增，黄=修正删除）
  → Dice 与体积变化（确定性计算）
  → 保存为独立修订版本（不覆盖原始预测）
  → 写入科研反馈记录
  → 修正历史可查
```

实测（BraTS20_Training_001，演示路径）：

| 项目 | 值 |
| --- | --- |
| 与预测的 Dice | WT 0.9255 / TC 0.9342 / ET 0.8825 |
| WT 体积变化 | +19.45 mL（修正新增 24,800 体素 / 修正删除 5,351 体素） |
| 版本 | r1，`demo_reference_simulation` |
| 原始预测文件 | 字节级未被修改（有测试断言） |

### 9.2 三条来源规则（工程强制，非文档约定）

1. **人工修正 ≠ 数据集参考标注**：分别存储、各自带 provenance 标签
2. **上传的修正 ≠ 医生审核**：`SOURCE_LABELS` 明确写「用户上传的修正掩膜」，
   并附「未经具备资质的医师审核」；代码中有测试断言标签里不出现「医生审核」字样
3. **演示 ≠ 真实人工修正**：演示路径全程标注 `demo_reference_simulation`，
   写入 DB 的备注、界面 pill、反馈记录三处都带「演示」标识

LLM **没有**任何修改掩膜或批准修正的工具。

### 9.3 本轮定位并修复的缺陷

| 问题 | 现象 | 根因 | 修复 |
| --- | --- | --- | --- |
| **阅片切片渲染极慢** | 每次切片切换约 3.5 s | `slice_masks_at` 把 9M 体素的布尔掩膜转成 float32（36 MB/区域/次）；`np.take` 沿非连续轴复制整卷 | 直接布尔切片 + 基础切片取视图 → **3.5 s → 23 ms（150×）** |
| **病例校验重复读盘** | 每次切换病例读 8 次 NIfTI | `validate_case` 绕过体数据缓存，校验后再渲染又读一遍 | 新增 `loader` 参数，app 传入 `cached_volume` |
| **切换病例残留待保存修正** | 病例 A 的待保存修正可能被保存到病例 B | `on_case_selected` 未清理 `pending_correction` | 切换时清空，并补测试 |
| **回调静默失效** | 一次编辑删掉了函数内的变量赋值，按钮点了没反应，无任何报错 | 回调只有在用户点击时才执行，单测覆盖不到 | 新增 `test_app_callbacks.py`（26 个测试）逐个调用全部 UI 回调 |

### 9.4 测试口径

`test_app_callbacks.py` 是专门为"回调静默失效"这类问题加的：
UI 回调只有在被点击时才运行，单元测试天然覆盖不到，
于是用一个模块把所有回调以最小合法 session 调一遍，断言不抛异常。
