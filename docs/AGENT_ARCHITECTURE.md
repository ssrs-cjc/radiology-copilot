# Agent 架构说明

> 双模型（DeepSeek / 本地 Qwen3-0.6B）· 工具注册 · 权限管理 · 执行追踪

---

## 1. 核心设计立场

> **LLM 不分析影像，也不计算数值。**

这是整个 Agent 层的出发点，也是所有其他决策的来源：

| 职责 | 由谁承担 | 为什么 |
| --- | --- | --- |
| 影像 → 肿瘤区域掩膜 | MONAI SegResNet | 经过验证的专用模型；LLM 看不到影像 |
| 掩膜 → 体积 / Dice | 确定性 Python 代码 | 医学数值不允许概率性生成 |
| 选工具、排顺序、组织语言 | LLM | 这是它真正擅长的事 |

由此推导出三条硬约束：

1. **体积只来自 `metrics.py`**，LLM 从不参与计算
2. **Agent 不能自行运行分割或审批报告**——那会消耗算力、改变系统状态
3. **没有 shell / 文件读写 / 删除类工具**

## 2. 整体结构

```
                    用户提问
                       │
                       ▼
        ┌──────────────────────────────┐
        │      run_agent_turn()        │
        │  按 provider 解析出 LLMConfig │
        └──────────┬───────────────────┘
                   │
       ┌───────────┴────────────┐
       ▼                        ▼
  llm_tool_calling        fixed_workflow
  （真实函数调用）         （确定性 Python 链路）
       │                        │
       └───────────┬────────────┘
                   ▼
        ┌──────────────────────────────┐
        │       ToolRegistry           │
        │  ┌────────────────────────┐  │
        │  │ 1. 工具名是否已注册？   │  │  否 → refused
        │  │ 2. JSON Schema 校验参数 │  │  否 → error（原因回灌给模型）
        │  │ 3. 执行工具            │  │
        │  │ 4. 记录状态与耗时      │  │
        │  └────────────────────────┘  │
        └──────────┬───────────────────┘
                   ▼
        ┌──────────────────────────────┐
        │  一致性校验                   │
        │  回答中的体积 / 病例编号       │
        │  与工具真实返回值比对          │
        └──────────┬───────────────────┘
                   ▼
        回答 + 执行追踪 + 一致性提示
```

## 3. 双模型接入

### 3.1 两个 provider 并存

| | DeepSeek | 本地 Qwen3-0.6B |
| --- | --- | --- |
| 配置来源 | `.env`（`LLM_API_KEY` 等） | `LOCAL_LLM_BASE_URL`（默认 `127.0.0.1:8080/v1`） |
| 运行时 | 官方 HTTPS API | llama.cpp，普通用户进程 |
| 推理设备 | 服务商 | **本机 CPU**（0 MB 显存） |
| 数据流向 | 结构化数据发往第三方 | **不出本机** |
| 平均耗时（实测） | 4.7 s | 207.8 s |

两者使用**完全相同**的系统提示词、工具 Schema、校验逻辑与安全机制。
详见 [MODEL_COMPARISON.md](MODEL_COMPARISON.md)。

### 3.2 三种选择语义

界面「推理模型」选择器：`DeepSeek` / `本地 Qwen3-0.6B` / `自动`。

| 选择 | 本地可用 | 本地不可用 |
| --- | --- | --- |
| `DeepSeek` | 用远程 | 用远程（报错说明配置缺失） |
| `本地` | 用本地 | **拒绝执行**，提示启动本地服务 |
| `自动` | 用本地 | **拒绝执行**，说明不会自动转远程 |

**默认是 DeepSeek**：交互式演示无法承受本地 CPU 每轮 100–425 秒的等待。

### 3.3 为什么不做静默外部回退

把病例结构化数据发往第三方服务，和在本机跑模型，是**两件性质不同的事**。
后者不产生数据出境，前者会。因此：

- 本地不可用时，`auto` **不会**自动改用 DeepSeek
- 切换到远程必须由用户明确选择（选 `DeepSeek` 即是确认）
- 一旦发生回退，配置对象带上 `fell_back` 标记，界面横幅显示
  `⚠ 已回退：<原因>`

每次回答都标注**实际服务商**：

```
服务商 deepseek-chat（远程 API · 数据将发送至第三方）
服务商 qwen3-0.6b（本地推理 · 数据不出本机）
```

### 3.4 传输层适配器

llama.cpp 服务端会应用模型的 chat template，但**不会**把 Qwen3 输出的
`<tool_call>{"name": ...}</tool_call>` 文本解析成结构化字段。项目内因此有一个适配器：

```python
extract_text_tool_calls(content) -> list[dict]
```

**它只做格式翻译**：

- 选哪个工具、传什么参数 —— 仍由模型决定
- 解析结果照样经过 JSON Schema 校验与工具注册表
- 有测试专门断言：**用文本态调用 `run_segmentation` 仍会被拒绝**、
  **非法参数仍会被拦下**

适配器不是绕过校验的通道，这一点由测试保证而非口头承诺。

## 4. 工具注册表

### 4.1 已注册工具（9 个）

| 工具 | 作用 | 三态语义 |
| --- | --- | --- |
| `get_case_info` | 病例基本信息 | 无病例 → `error` |
| `validate_mri` | 输入检查结果 | 未检查 → `error` |
| `run_segmentation` | 运行分割 | **永远 `refused`** |
| `get_segmentation_results` | 分割结果与模型版本 | 无结果 → `error` |
| `calculate_volume` | 读取已算好的体积 | 无掩膜 → `error` |
| `get_review_status` | 报告审核状态 | — |
| `get_model_evaluation` | 与参考标注的 Dice | 无参考标注 → 明确说明 |
| `generate_report_draft` | 生成报告草稿 | 未分割 → `refused` |
| `get_research_feedback` | 反馈统计 | — |

### 4.2 每个工具都有明确 JSON Schema

```python
Tool(name="run_segmentation",
     description="运行脑肿瘤分割模型。属于需要用户明确确认的操作，助手无法自行触发。",
     parameters={"type": "object",
                 "properties": {"confirm": {"type": "boolean",
                                            "description": "用户是否已明确确认运行"}},
                 "required": ["confirm"]},
     func=run_segmentation,
     requires_confirmation=True)
```

### 4.3 参数校验

模型是整条链路里**最不可信**的一环，因此它的输出被当作用户输入对待：

| 检查 | 行为 |
| --- | --- |
| 参数不是 JSON 对象 | `error` |
| 缺少必需字段 | `error`，列出缺哪些 |
| 出现未声明字段 | `error`，列出可用字段名 |
| 类型不符 | `error`（`bool` 与 `int` 严格区分） |
| 枚举越界 | `error`，列出合法取值 |

校验失败时，**错误原因会回灌给模型**，让它自行修正——而不是拼进 Python 调用。

## 5. 权限管理

### 5.1 需要用户确认的操作

`run_segmentation` 被设计成 **Agent 无法自行触发**：

```python
def run_segmentation(confirm: bool = False) -> ToolResult:
    if not confirm:
        return ToolResult(..., "refused", "运行分割模型需要用户明确确认", ...)
    return ToolResult(..., "refused", "请在界面上点击「运行 AI 分割」按钮以执行模型", ...)
```

**即使模型自己传 `confirm=true` 也返回 `refused`**——确认必须来自用户点击，
不能来自模型自己的参数。这防止了 LLM 绕过用户消耗算力或改变系统状态。

### 5.2 报告审批同理

`generate_report_draft` 只能写入 `pending_review` 修订；审批是人的动作，
Agent 够不到。审核记录作为独立修订版本保存，**不覆盖**原始模型预测。

### 5.3 工具边界

- 无 shell / exec / 文件读写 / 删除类工具（有测试扫描工具名）
- 发送给 LLM 的只有结构化字段：病例编号、序列、体积、模型版本
- **不含**原始影像、文件系统路径或患者身份信息

## 6. 执行追踪

### 6.1 记录内容

每次工具调用都记录：

```json
{
  "tool": "calculate_volume",
  "status": "ok",
  "summary": "WT 192.53 mL / TC 47.37 mL / ET 30.06 mL",
  "duration_ms": 4.1,
  "arguments": {},
  "error": ""
}
```

界面按序号展示，含**参数与耗时**——因此可以确认工具**确实执行了**，
而不只是模型描述了一遍。

### 6.2 三种模式严格区分

| 模式 | 触发条件 | 界面标识 |
| --- | --- | --- |
| `llm_tool_calling` | 配置 API 且通过函数调用探测 | 「LLM 工具调用模式（真实函数调用）」 |
| `fixed_workflow` | 未配置 API，或探测失败 | 「固定工作流模式（确定性 Python 工具链，未经 LLM 决策）」 |
| 报告模板 | 点击模板按钮 | 「已由确定性模板生成」 |

三者永不混淆：API 不可用时界面会如实标注，**不会伪装成成功调用大模型**。

### 6.3 函数调用能力探测

部分 OpenAI 兼容服务会**静默忽略** `tools` 参数——模型会"叙述"工具调用却没有真正执行。
因此启动时做一次真实探测：

```
依次尝试 tool_choice: 强制指定函数 → "required" → "auto"
只要有一次返回真实 tool_calls，即判定支持
```

用 `auto` 探测是不可靠的：模型有权选择用散文回答。

### 6.4 回答一致性校验

```python
verify_answer_consistency(answer, tool_results, expected_case_id)
```

- 回答中出现的每个 **mL 数值**必须能在工具返回值中找到（容差 0.05 mL）
- 回答中出现的**病例编号**必须是当前病例

不符时**在回答旁标注提示**，而不是用模型的说法覆盖工具结果，也不改写回答。

校验器本身也踩过坑，都已修复并加了回归测试：

| 误报 | 原因 |
| --- | --- |
| 正确的回答被判「病例编号不一致」 | 正则把标签约定字符串 `brats_2020` 误认成病例编号 |
| 引用 `0.001 mL`（体素体积）被判体积不符 | 采集器只读区域总体积，遗漏 `voxel_volume_ml` |

### 6.5 审计留存

每个回合写入 SQLite `agent_traces` 表：用户提问、模式、工具调用、最终回答、模型名、时间。
另有脱敏执行记录写入 `outputs/agent_e2e_record.json`，**写出前做泄漏检查**
（出现 API Key / Base URL / 本机路径则拒绝写出）。

## 7. 失败处理

| 失败 | 行为 |
| --- | --- |
| API 未配置 | 降级到固定工作流，界面明确标注 |
| 端点不支持函数调用 | 同上 |
| 模型调用超时/报错 | 降级到固定工作流，保留错误信息 |
| 单轮工具调用超过 6 轮 | 停止并提示缩小问题范围 |
| 本地模型不可用 | **拒绝执行**（不静默转远程），提示启动本地服务 |

**固定工作流**是关键词路由到确定性 Python 工具链，结果直接汇总。
它不伪装成 LLM 决策——界面上写的是"未经 LLM 决策"。

## 9. 测试

`tests/test_agent_llm.py`（74 个）覆盖：

- 工具参数校验（类型 / 必需项 / 未声明字段 / 枚举 / bool-int 区分）
- 工具调用失败与错误反馈
- API 未配置时的降级行为
- 非法工具名称拒绝
- 未授权状态修改拒绝（含模型自己传 `confirm=true`）
- 报告数值与真实工具结果一致
- 工具调用记录包含真实执行状态与耗时
- 切换病例后不会混用此前病例的数据
- provider 选择与**不做静默外部回退**
- 文本态 `<tool_call>` 解析、思考块剥离、适配器不放宽校验
